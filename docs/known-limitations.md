# Known limitations

These are implementation follow-ups identified during the documentation audit, not promised functionality.

- **Kanban keyboard navigation:** five columns are rendered, but `navigateKanbanRight` in `internal/gui/shortcuts.go` still bounds its search with `c < 4`. The final PR Merged column cannot be reached by moving right from another column. Select a card with the mouse instead. Fix the bound and add navigation coverage in a separate code change.
- **Nix packaging:** `flake.nix` has a placeholder dependency hash and needs its Fyne build/runtime dependencies validated. It is not advertised as an installation method until verified.
- **GitLab checkout:** status and creation support GitLab, but fetch-to-worktree uses GitHub helpers. Extend the provider abstraction before advertising MR checkout.
- **Issue worktree inputs:** issue-created worktrees currently accept only a positive GitHub issue number or `owner/repo#number`. GitHub issue URLs, GitLab issues, and base-branch selection are not supported.
- **Terminal reuse:** associations are in memory. After restarting Biomelab, only regular terminals still inside a known worktree can be rediscovered; external sandbox sessions cannot be associated reliably. Targeted activation supports Terminal.app/iTerm2 on macOS and identifiable X11 windows on Linux. macOS ARM desktop acceptance is still pending; see the [terminal reuse checks](terminal-reuse-validation.md).
- **Windows terminal focus (reuse within a session):** pressing Enter on a card whose terminal is already open raises that terminal instead of opening a second one, and repeat Enter never opens a duplicate. A Windows Terminal window Biomelab launched is raised by the per-session name it assigns at launch (`wt -w <name> focus-tab`); this survives the shell or agent overwriting the tab title. A classic PowerShell console is raised by its recorded window handle when its exact title still matches.
  - **Exception — OS-delegated PowerShell fallback:** if `BIOME_TERMINAL` is set to `powershell.exe`/`pwsh.exe` **and** the Windows *default terminal* is Windows Terminal, the OS opens that PowerShell inside Windows Terminal itself. Biomelab never invoked `wt.exe`, so it assigned no window name to target, and the delegated console exposes no usable handle to the visible window — its `GetConsoleWindow` is a hidden pseudoconsole and `WT_SESSION` is empty — so it cannot be mapped to the real window safely. Biomelab reports a manual-switch message and still never opens a duplicate. To make these sessions focusable, either leave `BIOME_TERMINAL` unset so Biomelab launches Windows Terminal itself (named and focusable), or set the Windows default terminal to "Windows Console Host" so the fallback stays a focusable classic console. Do not change the OS default terminal merely to make a check pass; record the actual host.
- **Windows terminal reuse after a restart:** associations are in memory only. Discovery matches a shell to a worktree by the shell's process working directory, but a launched Windows shell deliberately does **not** adopt the worktree as its process working directory: Windows keeps an open handle on a process's working directory, which would make removing the worktree delete its contents and then fail on the directory itself. As a result a restarted Biomelab does not rediscover a still-open terminal — the card shows no terminal for a session it opened, and Enter opens a new one. Native desktop acceptance is still pending; use the [interactive Windows verification](windows-focus-validation.md).
- **Windows sandbox worktree cards:** the main card (`sbx run`) works. A linked worktree card starts in the right container directory — host paths are translated with `sandbox.ContainerPath`, since sbx mounts `C:\a\b` at `/c/a/b` — but git is unusable there: `git worktree add` records an absolute host `gitdir:` in the worktree's `.git` file, and `C:/...` does not resolve inside the container, so the agent sees `fatal: not a git repository`. Making worktrees portable needs relative `gitdir` pointers, which affects worktree creation on every platform.
- **Windows focus validation:** background helper commands suppress console allocation, and refresh/action requests are bounded. Resolution of the reported constant focus loss still requires the [interactive Windows verification](windows-focus-validation.md); native/headless tests cannot establish foreground behavior on the affected desktop.

These limits should be removed from the guides only after the corresponding behavior has been implemented and checked.
