# Known limitations

These are implementation follow-ups identified during the documentation audit, not promised functionality.

- **View state:** Board/List/Grid selection, inspector visibility, main-card disclosure, scroll offsets, and font zoom are kept for the current app run; they are not saved across restarts. The light/dark theme and repository order are saved.
- **Board status:** lifecycle columns come from PR/MR provider data. Cards cannot be dragged between columns to change request state.
- **Nix packaging:** `flake.nix` has a placeholder dependency hash and needs its Fyne build/runtime dependencies validated. It is not advertised as an installation method until verified.
- **GitLab checkout:** status and creation support GitLab, but fetch-to-worktree uses GitHub helpers. Extend the provider abstraction before advertising MR checkout.
- **Issue worktree inputs:** issue-created worktrees currently accept only a positive GitHub issue number or `owner/repo#number`. GitHub issue URLs, GitLab issues, and base-branch selection are not supported.
- **Integrated terminals:** macOS/Linux use an in-app PTY drawer; Windows uses an app-owned ConPTY drawer and requires Windows 10 version 1809 or later, or Windows 11. If ConPTY is unavailable, startup reports an error and the user can explicitly choose **Open in external terminal**. History is limited to 1,000 lines per session and is not persisted. Terminals do not import existing OS shells or guarantee agent conversation recovery. The current widget uses a documented [local compatibility patch](../third_party/fyne-terminal/BIOMELAB.md). Native Windows desktop acceptance and interactive agent/TUI acceptance on Linux and macOS ARM remain pending; automated checks are not a substitute for that desktop coverage.
- **Integrated terminal cleanup on macOS/Linux:** Stop, restart and worktree deletion end the shell's process group and wait up to five seconds for it to exit. An interactive shell moves each job into its own process group, so a job that ignores hangup (for example `nohup cmd &`) is not stopped and can keep running in a deleted worktree. Windows ends every descendant through a Job Object.
- **Return-to-workspace chord vs. 1Password:** the integrated terminal uses Ctrl+Shift+Space to hand focus back to the workspace. On Windows and Linux, 1Password registers the same chord system-wide for Quick Access by default, so it never reaches Biomelab and instead opens 1Password (and possibly a Windows Hello prompt). Rebind or disable the Quick Access shortcut in 1Password, or leave the terminal with the mouse. Observed on Windows 11 during native validation.
- **Terminal application mouse input:** the wheel scrolls terminal history; wheel events are not yet forwarded as mouse reports to alternate-screen applications. Use their keyboard navigation. Native agent/TUI acceptance remains necessary before claiming full emulator compatibility.
- **External terminal reuse:** associations are in memory. After restarting Biomelab, only regular terminals still inside a known worktree can be rediscovered; external sandbox sessions cannot be associated reliably. Targeted activation supports Terminal.app/iTerm2 on macOS and identifiable X11 windows on Linux. macOS ARM desktop acceptance is still pending; see the [terminal reuse checks](terminal-reuse-validation.md).
- **Windows external-terminal focus:** this limitation applies to the explicit **Open in external terminal** action; Enter opens the integrated terminal. Repeating the external action reuses or raises a terminal Biomelab previously opened and does not create a duplicate. A Windows Terminal window Biomelab launched is raised by its per-session name (`wt -w <name> focus-tab`), even after the shell or agent changes the tab title. A classic PowerShell console is raised by its recorded window handle when its exact title still matches.
  - **Exception — OS-delegated PowerShell fallback:** if `BIOME_TERMINAL` is set to `powershell.exe`/`pwsh.exe` **and** the Windows *default terminal* is Windows Terminal, the OS opens that PowerShell inside Windows Terminal itself. Biomelab never invoked `wt.exe`, so it assigned no window name to target, and the delegated console exposes no usable handle to the visible window — its `GetConsoleWindow` is a hidden pseudoconsole and `WT_SESSION` is empty — so it cannot be mapped to the real window safely. The external action reports a manual-switch message and still never opens a duplicate. To make these sessions focusable, either leave `BIOME_TERMINAL` unset so Biomelab launches Windows Terminal itself (named and focusable), or set the Windows default terminal to "Windows Console Host" so the fallback stays a focusable classic console. Do not change the OS default terminal merely to make a check pass; record the actual host.
- **Windows external-terminal reuse after a restart:** associations are in memory only. Discovery matches a shell to a worktree by the shell's process working directory, but a launched Windows shell deliberately does **not** adopt the worktree as its process working directory: Windows keeps an open handle on a process's working directory, which would make removing the worktree delete its contents and then fail on the directory itself. After a restart, the explicit external-terminal action does not rediscover that shell and may open another external session. Native desktop acceptance is still pending; use the [interactive Windows verification](windows-focus-validation.md).
- **Windows sandbox worktree cards:** the main card (`sbx run`) works. A linked worktree card starts in the right container directory — host paths are translated with `sandbox.ContainerPath`, since sbx mounts `C:\a\b` at `/c/a/b` — but git is unusable there: `git worktree add` records an absolute host `gitdir:` in the worktree's `.git` file, and `C:/...` does not resolve inside the container, so the agent sees `fatal: not a git repository`. Making worktrees portable needs relative `gitdir` pointers, which affects worktree creation on every platform.
- **Windows focus validation:** background helper commands suppress console allocation, and refresh/action requests are bounded. Resolution of the reported constant focus loss still requires the [interactive Windows verification](windows-focus-validation.md); native/headless tests cannot establish foreground behavior on the affected desktop.

These limits should be removed from the guides only after the corresponding behavior has been implemented and checked.
