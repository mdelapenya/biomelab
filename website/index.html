Safe sandboxes for living code

Monitor your AI agents across worktrees

biomelab is a desktop dashboard for managing git worktrees, coding agents, and Docker Sandboxes across all your repositories.

  • Multi-repo visibility
  • Sandboxed isolation
  • Live PR and CI status

The Problem

Agent sprawl is real

You've got your favorite coding agent running on a feature branch, another instance on a bug fix, and a third on a refactor — all in the same repo, in parallel. Which branch is which? Is anything dirty? Did that PR pass CI? You alt-tab between terminals trying to piece it together.
The Dashboard

One dashboard, every worktree

Register all your repositories. See every branch, every agent, every PR, updating in real time.

📂

Multi-repo

Register all your repositories. Switch between host and sandbox modes in the projects panel. Drag repository handles to save your preferred order.

🤖

Auto-detect agents

Claude, Copilot, Codex, Kiro, OpenCode, Gemini. Detected by process scanning, shown on each card.

💻

Auto-detect IDEs

VS Code, Cursor, Zed, Windsurf, GoLand, IntelliJ, PyCharm, Neovim, Vim. Tracked per worktree.

⚡

Live status

Local activity and dirty state refresh every 5 seconds. PR/MR, reviews, CI, and sync status refresh every 30 seconds by default.

🎞

Agent audit trail

re_gent integration. View recorded prompts, replies, and tool calls with the optional host rgt integration. Press l to open the activity window; export raw JSON in one click.

🩺

System dependencies

One systray entry shows the status of every CLI biomelab uses (gh, glab, sbx, rgt) with install hints and docs — no more guessing why a feature is grey.

⌨️

Keyboard-first

Use contextual shortcuts or select cards with the mouse. Dark/light themes, zoom, and tray controls keep the desktop app close at hand. Press ? on this page for demo shortcuts.

Docker Sandboxes

Sandboxed agent execution

Each agent gets an isolated Docker environment per project, shared by its worktrees. Toolchains run inside the sandbox; workspace files stay available on your host.

🔒

Isolated Environments

One sandbox VM per agent per repo. Its worktrees share the execution environment. Source files stay shared with the host, so agent edits are visible there.

🧩

One Sandbox Per Agent

Claude gets one sandbox, Codex gets another. Clean separation of toolchains and state.

⌨️

One Setup Flow

Press n in the projects panel, choose an agent, optionally add compatible kits, and create. Kits install from Docker Hub OCI artifacts. Start, stop, and remove from the dashboard.

Workflow

From project to pull request

The core loop, from creating a worktree to shipping a pull request.

1

Register

biomelab auto-adds your current repo on first launch. Or press a to add more.

For a sandbox, press n in the projects panel. Choose your agent and answer “Do you want to add kits?” Choose Yes to load compatible kits, or No to skip them, then confirm creation. No second setup in the worktree panel. Kits are selected at creation time only.

2

Create worktrees

Select the main worktree card, press c, enter a branch name, and confirm.

3

Open in terminal

Press Enter. Opens the sandbox agent session, or activates an existing host terminal or opens a new one. In host mode, start your agent there.

4

Agent auto-detected

In host mode, process scanning finds supported agents and shows their activity on the card. Sandbox sessions use the selected agent integration.

5

Send PR

Press Shift+P on a linked card, review the remote and confirmation, then push and create a PR/MR. Existing requests use push-only mode.

6

PR status flows in

PR #42 fix auth (open) ✓. CI checks, merge status, all on the card.

Task Notes

Brief your agent, draft your PR — in the same place

A Markdown editor scoped to each worktree. Save a title and description beside the code, share them with your sandbox agent, and choose to use them when creating a PR/MR.

📝

Note next to the code

Press m or right-click a card to open the editor. Single-line PR title above, multi-line Markdown body with a live preview pane.

🐋

Reaches your agent

Stored inside the worktree, so the file gets mounted into the sandbox microVM. Your agent reads the title and Markdown from .biomelab/ inside the worktree.

🚀

Becomes the PR

On Shift+P, biomelab offers to use your prepared title and description in place of the commit-derived defaults. Skip the rewrite — the note is the description.

Extension point

# Any skill, agent, or script can populate the two artifact files:
<worktree>/.biomelab/pr-title.md      # single-line PR title
<worktree>/.biomelab/note.md          # PR description (Markdown)

# biomelab turns them into the actual PR on Shift+P:
gh pr create --title "$(cat .biomelab/pr-title.md)" \
             --body-file .biomelab/note.md

Write to those paths and biomelab handles the rest. Falls back to commit-derived --fill when files are absent.

Get Started

Install in seconds

Available on macOS, Linux, and Windows. Pick your preferred method. See installation and nightly builds, including macOS Gatekeeper guidance, and platform limitations.

brew install --cask mdelapenya/tap/biomelab

Source builds require Go (see go.mod), CGO, a C compiler, and platform graphics libraries. Follow the source build guide.

go install github.com/mdelapenya/biomelab/cmd/biomelab@latest
